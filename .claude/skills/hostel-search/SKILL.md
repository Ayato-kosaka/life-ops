# 宿（ホステル）を調べる（Google マップ）

Chrome で Google マップを操作し、都市・日程ごとの安いホステルと価格を表にする。**調べるところまで**で、予約・決済・ログイン・個人情報の入力はしない。

## Chrome の使い方

- その環境にある Chrome の操作手段を使う（Claude in Chrome の `mcp__claude-in-chrome__*`、EC2 上の Chrome を CDP で操作する
  `Ayato-kosaka/live-streaming` の `ec2-chrome` スキルなど）。CDP で操作するときは、画面の要素を JS で探して座標をクリックし、`innerText` を読む。
  タブが応答しなくなったら Chrome を起動し直して続きから進める（取得済みの結果はファイルに貯め、済んだものは飛ばす形にする）
- Bot 判定や確認画面が出たら、すり抜けようとしない。人が解けるならそれを待ち、解けなければ止めて報告する。
- 表示は日本語・日本円にする（`https://www.google.com/maps?hl=ja`、通貨は設定で JPY）。

## 入力（足りなければ聞く）

| 項目 | 既定 |
|---|---|
| 都市・日程 | チェックイン日〜チェックアウト日。日程が仮なら前後1日ずらした価格も見る |
| 人数 | 1名 |
| 部屋 | 指定が無ければ最安（ドミトリーのベッド可） |

## 手順

1. Google マップで、地図を都市の中心に合わせて「hostel」と検索する（下の URL）。日付をチェックイン・チェックアウトに、人数を1名にする。
   「hostel <都市> <国>」のように都市名を入れて検索しない。出る宿が数件に減り、安い宿が漏れる（2026-11-08 にブカレストで5件と34件の差が出た）。
2. **一覧を全部読み、価格の上限を下げながら読み直す**: まず上限なしで一覧を最後までスクロールして読む。続けて上限を
   ¥4,000 → ¥3,000 → ¥2,500 → ¥2,000 → ¥1,500 のように下げ、そのたびに一覧を最後まで読む（上限を下げると、上限なしでは
   一覧に出なかった安い宿が出てくる）。0件になったら止める。全部の結果を宿の名前でまとめ、**一覧の価格の安い順に並べる**。
   5件以上残るところで止めたり、上限を上げながら探したりしない（安い宿を取りこぼす）。
3. **上位の宿を開いて確認する**: 安い順に5件程度、評価で除かずに宿の詳細を開き、次を控える。
   - 掲載先ごとの価格（Booking.com・Hostelworld・公式サイトなど）と、いちばん安い掲載先
   - 税・サービス料・都市税（現地払い）が含まれるか
   - 部屋の種類（ドミトリー何人部屋・男女混合か、個室か）
   - 評価（点数と件数）、場所（中心部・駅/バスターミナルからの距離）
   - 冬は暖房、配信・作業するなら Wi-Fi の評判が分かれば添える
4. 最安の宿を先頭に置き、評価が低い（目安3.5未満）・件数が極端に少ない宿は注記する（除かない）。
   一覧の価格は掲載先の1つの価格で、価格の上限もこの価格で効く。詳細の「価格を比較」のほうが安いことが多いので、両方を書く。
5. 公式サイトがあれば開き、同じ日程の価格が安ければそれも書く。

### Google マップの画面の操作（2026-11 時点）

- 検索は `https://www.google.com/maps/search/hostel/@<緯度>,<経度>,13z?hl=ja&gl=jp`（地図の範囲で探す。小さい町は 14z）
- 日付は `aria-label` が「チェックインを 1 日後に設定」「チェックアウトを 1 日前に設定」などのボタンで1日ずつ動かす。
  今の日付は、そのボタンの親要素の文字（`11月12日(木)` の形）から読む。曜日の「(月)」も「月」なので、日付2つの並びで判定する。
  指定できるのは30泊まで。遠い日付へ動かすときは、泊数が30を超えないようにチェックインとチェックアウトを交互に動かし、
  最後に表示の日付が狙いどおりかを確かめる（ずれたまま読まない）
- 人数は `aria-label` が「利用者 N 人」のボタンを押し、`[role=menuitemradio]` の「利用者 1 人」を選ぶ
- 価格は `[role=slider][aria-label=最高料金]` にフォーカスして矢印キーで動かす（`aria-valuenow` が今の上限）。
  1回の刻みは都市ごとに違う（¥600 など）ので、狙った額ちょうどにはならない。並べ替えに「料金の安い順」は無い
- 一覧は `[role=feed]` の子要素。件数が増えなくなるまで下へスクロールする。「スポンサー」の行は広告なので重複を除く。
  一覧には価格の出ない宿も混ざる（Google で予約できない宿）
- 一覧の価格は1泊あたり。宿のリンク（`/maps/place/…`）には日付と人数が入っているので、そのまま開けば同じ条件の
  「価格を比較」（掲載先ごとの価格）が読める。Vio.com・Tripadvisor などは比較サイトで、予約は別の掲載先になる

## 出力

都市・日程ごとに次の表を作り、依頼元（Issue など）に貼れる Markdown で返す。

| 宿 | 部屋 | 1泊 | 総額（税込の目安） | 安い掲載先 | 評価 | 場所・メモ | 出典 |
|---|---|---:|---:|---|---|---|---|

- 表の上に**取得日時**と泊数を書く。価格は日程と残室で変わる前提で扱う。
- Google マップの宿のリンク（`maps.google.com/?cid=` など、公開された宿のページ）を出典にする。
